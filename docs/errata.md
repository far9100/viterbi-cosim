# 勘誤：凍結文件中已被實測推翻的敘述

本檔是凍結文件勘誤的**中央索引**。

## 為什麼需要它

`CLAUDE.md` §5.1 規定凍結文件不得回頭修改——凍結的意義正在於「它的內容早於它所管轄的量測」，
事後改動會讓時間戳失去證據力。這條紀律是對的，本檔不放寬它。

但它有一個副作用：有幾條敘述**在量測之後被推翻了**，更正只寫進了 `docs/report.md`
與 `docs/thesis.md`。於是**單獨閱讀那份凍結文件的人，看到的仍然是被推翻的說法**，
而且沒有任何線索告訴他去別處查。

解法是「原文一字不改，另外追加」：

1. 每份被勘誤的凍結文件在**檔尾**追加一條 `▼▼▼` 帶（沿用 `docs/falsification.md`
   在 M5 之後追加裁決時發明的格式），帶內寫勘誤；凍結本體一個字都不動。
2. 本檔是索引，讓「這個專案有哪些東西被推翻過」可以一次看完。
3. `scripts/check_paper_numbers.py` §6 對兩者做**雙向對帳**，並把
   「凍結本體逐位元組等同於凍結 tag 裡的 blob」從一句紀律變成一條會紅燈的檢查。

## 不在本檔範圍內的東西

- **被推翻的「交付物」不算勘誤。** 規格書 §7 要求的「功耗 vs SNR 依賴曲線」被實測推翻，
  但規格書不是凍結文件（它有修訂記錄段，可就地修訂），該修訂寫在規格書 §7 的修訂框裡。
- **事後追加的檢定不算勘誤。** gate `M9-5` 的斜率檢定不在 `docs/lowpower_baseline.md` 裡，
  它是量測之後才追加的，如實標示為「事後」，但凍結判準本身沒有被改動，所以不是勘誤。
- **點估計錯誤不算勘誤。** `docs/falsification.md` §3.2 的 α 點估計錯了 3.4 倍，
  但那份文件的 §5.2 自己就如實記載了這件事——凍結文件內部已經自我更正的，不需要外部勘誤。

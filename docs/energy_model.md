# 總能量模型：常數、假設與計價方式

> 本文件在任何能量量測開跑之前提交（CLAUDE.md §1.2）。所有常數在此定案；M5 的 script 只讀本文件
> 定義的參數，不得在程式碼裡另立數值。任何一個常數要改，必須改本文件並重新 commit，且說明理由。

## 0. 為什麼要有這份文件

規格書 §7 給了 `E_total = E_tx + E_dec` 的骨架，但沒有定義 `N0`、沒有定義天線增益，也沒有指定
**「固定符號率」還是「固定資訊率」**。最後那一項不是細節：R=1/2 的編碼鏈路在固定符號率下要花
兩倍的空中時間，因而付兩倍的收發電路能量。這一項的有無會讓 d\* 差兩個數量級。不先定死，
最後的數字就無法被檢驗。

## 1. 物理常數

| 符號 | 值 | 來源 |
|---|---|---|
| k | 1.380649e-23 J/K | Boltzmann（SI 定義值） |
| T₀ | 290 K | 標準參考溫度 |
| k·T₀ | 4.00388e-21 J | = −173.98 dBm/Hz |
| c | 2.99792458e8 m/s | 光速（SI 定義值） |
| f_c | 2.4 GHz | 載波（規格書 §7） |
| λ | 0.124913 m | = c / f_c |

## 2. 系統參數（預設值 + 掃描範圍）

| 參數 | 預設 | 掃描範圍 | 說明 |
|---|---|---|---|
| F（接收機雜訊指數） | 6 dB | {3, 6, 10} dB | 低功耗 2.4 GHz 收發機的典型值。**規格書完全沒定義這一項，但 N0 = k·T₀·F 直接乘進 E_tx，d\* ∝ F^(1/n)。** |
| N0 | 1.5940e-20 J | 隨 F | = k·T₀·F |
| G_t, G_r | 0 dBi | 固定 | 等向天線。規格書未定義，此處明確固定為 0，不偷藏增益。 |
| η_PA | — | [0.1, 0.5] | 規格書 §7 指定。 |
| n（路徑損耗指數） | — | 2.0 / 3.5 | 2.0 = 自由空間；3.5 = 室內。雙軸呈現（規格書 §7）。 |
| R_s（符號率） | 1 Msym/s | 固定 | **模型 B 的關鍵假設**，見 §4。 |
| P_circuit | 60 mW | {20, 60, 120} mW | = P_ct + P_cr（發射端 + 接收端前級，兩端都要計入「每交付位元」的能量）。 |
| f_clk（解碼器） | 100 MHz | 隨合成 | 見 §5。 |
| 目標 BER | 1e-5 | 固定 | 規格書 §7。 |

**路徑損耗**（d₀ = 1 m 為參考點）：

```
L(d) = (4π/λ)² · d^n = 1.01174e4 · d^n        # d₀=1 m 處為 40.05 dB
```

n=2 時這就是自由空間 Friis；n=3.5 時是以同一個 1 m 參考點外推的室內模型。

## 3. 兩個模型

```
模型 A（規格書 §7 原樣）：
    E_total / info bit = E_tx + E_dec

模型 B（WSN 文獻標準，Cui/Goldsmith/Bahai 類）：
    E_total / info bit = E_tx + E_dec + P_circuit · T_air
```

兩者並陳，不擇一。理由：模型 A 是規格書寫死的東西，必須如實跑出來；模型 B 才是能跟低功耗
WSN/BAN 文獻對話的模型（規格書 §0 自己說「此 crossover 在低功耗 WSN/BAN 文獻中是已知效應」——
那些文獻用的就是模型 B）。只報 A 會讓結果無法與前人比較；只報 B 會偏離規格書。

```
E_tx  = (Eb/N0)_req · N0 · L(d) / η_PA
E_dec = P_decoder(f_clk, Q, W, D, SNR) / f_clk        # full-parallel 為 1 info bit/cycle
T_air = 1 / (R_s · R)                                  # 每個 info bit 的空中時間
```

- `(Eb/N0)_req`：該組態在 BER=1e-5 下所需的 Eb/N0，取自量測（線性值，不是 dB）。
- `P_decoder`：來自 OpenSTA 的 SAIF 標註功耗，**分組態、分 SNR**。

## 4. 固定符號率 vs 固定資訊率（規格書漏掉、但決定 d\* 兩個數量級的一項）

本專案採**固定符號率** `R_s = 1 Msym/s`。後果：

| | 每 info bit 的符號數 | T_air | 電路能量 |
|---|---|---|---|
| 未編碼 | 1 | 1 µs | P_c × 1 µs |
| K=7, R=1/2 | 2 | 2 µs | P_c × 2 µs |

**編碼鏈路多付 `P_circuit × 1/R_s` 的電路能量**（預設值下 = 60 mW × 1 µs = **60 nJ/info bit**）。

這一項在模型 B 裡是**支配項**：它比 E_dec（~0.1 nJ 級）大 600 倍。這正是低功耗 WSN 文獻裡
「短距離下編碼不划算」的真正機制——不是解碼器耗電，而是**編碼把空中時間變兩倍**。

（另一種選擇是固定資訊率：編碼端把符號率提高到 2 Msym/s，兩者 airtime 相同，電路能量抵銷，
模型 B 退化為模型 A。本專案不採這條，因為它隱含「頻寬免費」，與 WSN 的實際限制不符。
此選擇在報告中須明講。）

## 5. E_dec 的計價方式

`E_dec = P_decoder / f_clk`，其中 full-parallel 架構為 1 info bit/cycle，故「每 cycle 的能量」
就是「每 info bit 的能量」。

**假設：解碼器在 frame 之間被 power-gated。** 鏈路的資訊率只有 `R_s · R` = 0.5 Mbps，而解碼器
跑在 100 MHz，工作週期只有 0.5%。若不做 power gating，閒置時的漏電會額外貢獻
`P_leak × (1/R_info − 1/f_clk)`，把 E_dec 灌大約 200 倍。這個假設必須在報告中明講。

為了讓任何 f_clk 下的 E_dec 都能被重算，`data/results.csv` 必須**分開記錄**：
- `e_dyn_per_bit`（動態能量/bit，與 f_clk 無關）
- `p_leak`（漏電功率，與 f_clk 無關）
- 則 `E_dec(f_clk) = e_dyn_per_bit + p_leak / f_clk`

## 6. 已知的計價偏差（必須在報告中揭露，不得隱藏）

1. **Survivor 記憶體用 flop 陣列，不是 SRAM macro。** 真實解碼器會用 SRAM（ORFS image 內就有
   `sky130_sram_1rw1r_64x256_8`，64 bits × 256 列，正好對得上 3D ≤ 256）。flop 陣列會**高估
   面積與 E_dec，進而高估 d\***。方向明確：本專案報的 d\* 是**上界**。
2. **ADC 能量未計入。** 軟判決需要 Q-bit ADC，其能量約 ∝ 2^Q（Walden FoM）。排除它會**系統性
   低估大 Q 的代價**——而「d\* vs Q」正是頭條圖。M5 會附一條 Walden FoM 的敏感度線
   （`E_ADC ≈ FoM × 2^ENOB × f_s`），但不宣稱它是量測值。
3. **未計入編碼器能量**（幾十個閘，可忽略）與**未編碼路徑的 slicer 能量**（1-bit 比較器，可忽略）。
4. **glitch 功率**：gate-level 模擬採 `-DFUNCTIONAL -DUNIT_DELAY`，非真實 SDF 標註延遲，
   glitch 行為只是近似。方向不明，須揭露。

## 7. 可重生性

本文件的每個常數在 `scripts/energy_model.py` 中有對應的具名常數，且該檔的單元測試會斷言
「程式碼中的值 == 本文件表格中的值」。`scripts/check_paper_numbers.py` 會再檢查報告引用的
每個 d\* 數字都能由 `data/results.csv` + 本文件的常數重算出來。

## 勘誤 E-01（2026-07-31）

**原文（§5）**：「若不做 power gating，閒置時的漏電會額外貢獻
`P_leak × (1/R_info − 1/f_clk)`，把 E_dec 灌大約 **200 倍**。」

**更正**：200 倍是**漏電那一項**的比值（`(1/R_info)/(1/f_clk) = 2e-6/1e-8`），
不是 E_dec 的比值。漏電只佔本設計總功耗的 **0.00027%**（64 nW vs 24 mW），
所以把它放大 200 倍對 E_dec 幾乎沒有影響。實測：關掉 power gating 之後
**E_dec 最多變 0.055%、d\* 最多變 0.017%** ⇒ 這個假設其實無關緊要。
對報告是好消息（少一條 caveat），但本文件印的量級不得沿用。

**證據**：`data/gates.csv` 的 gate `M5-4`、`data/results_m5_sensitivity.csv`。

**發現於**：CHANGELOG `2026-07-15-12`。

## 勘誤 E-02（2026-07-31）

**原文（§1 常數表、§3 路徑損耗式）**：λ 印 **0.124913** m；`L(d) = (4π/λ)² · d^n = 1.01174e4 · d^n`。

**更正**：兩者都是**導出值**的印刷誤差，不是模型錯誤。
`c/f_c = 0.12491352417`，正確的六位小數是 **0.124914**；
`(4π/λ)² = 1.012047e4`，與文件印的 1.01174e4 相對差 **3.04e-4**。
`scripts/energy_model.py` 是從原始常數（c、f_c）計算的，所以**所有已發表的數字都不受影響**；
受影響的只有本文件印出來的那兩個中間值。

**證據**：`tests/test_energy_model.py::test_lambda`、`::test_path_loss_at_1m`
——這兩條測試以本文件為 oracle，正是它們把差異找出來的。

**發現於**：CHANGELOG `2026-07-29-05`。

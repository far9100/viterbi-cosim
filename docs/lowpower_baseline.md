## 0. 為什麼需要這一份

`docs/report.md` §4 的核心結論是一個**負面結果**：解碼器總功耗在 1→5 dB 只變動 1.0%，
而機制是「編碼把資料路徑的位元活動釘在最大熵」。

這個結論有一個尚未被檢驗的前提：**它是在一個未最佳化的設計上量到的。**

- `ppa/synth.py` 只跑 `synth` / `dfflibmap` / `abc -liberty`，**全流程沒有任何 clock gating**。
- survivor 記憶體用 flop 陣列（register exchange），不是 SRAM macro。
- 沒有 power-aware 合成、沒有折疊架構。

後果：traceback 佔 43–54% 的功耗，而它的活動**結構性地**與 SNR 無關；
唯一帶 SNR 資訊的路徑度量 `pm`（R² = 0.913、全距 3.34%）只佔 7–13% 的功耗，
被稀釋到總功耗只剩 ~1%。

**所以必須回答：把那個「與 SNR 無關的大分母」縮小之後，null 還在不在？**
兩種結果都能寫成論文，但不先量就寫，等於賭運氣。

## 1. 「最佳化過的基準線」的定義（三態）

| 態 | 定義 | 狀態 |
|---|---|---|
| **B0 現況** | 現行 `ppa/synth.py`：無 clock gating、flop 陣列 survivor | 已有（M5） |
| **B1 +clock gating** | Yosys `clockgate -pos sky130_fd_sc_hd__dlclkp_1 GATE:CLK:GCLK`，其餘不變 | M9 |
| **B2 +memory traceback** | survivor 改為 SRAM/記憶體式回溯，取代 register exchange | M9（若時程允許） |

三態使用**完全相同**的 RTL 源碼（B2 除外）、相同的激勵、相同的 SAIF→OpenSTA 路徑，
只有合成選項不同，以確保差異只來自最佳化本身。

## 2. 事前預測（**這一節是本文件的重點，量測後不得修改**）

### 2.1 B1（clock gating）的預測：**節省有限，null 會存活**

這不是猜的，是從 `rtl/ctrl.sv` 讀出來的：

```
assign stage_en = (st == S_RUN) && in_valid;
```

功耗量測窗內 `in_valid` 每個 cycle 都為高，故 `stage_en` 的 duty cycle 是

```
T / (T + D)  ，  T = NINFO + 6
Q4 W10 D64、NINFO=1024：1030 / (1030 + 64) = 94.1%
Q3 W8 D32  、NINFO=1024：1030 / (1030 + 32) = 97.0%
```

**clock gating 只能把那 3–6% 的閒置 cycle 的時脈關掉。** 而且 register exchange
在作用中的每個 stage **真的會改寫全部 64 個暫存器**——那不是可以被 gate 掉的浪費，
是演算法本身要求的活動。

> **預測 P1**：B1 相對 B0 的總功耗下降 **< 10%**。
> **預測 P2**：B1 下總功耗對 SNR（1→5 dB）的變動仍 **< 2%** ⇒ **null 存活**。
> **預測 P3**：clock gating 會顯著降低 `stage_en` 的扇出（B0 實測 8683 sinks），
> 因為每個 flop 的 enable 腳被 ICG 取代 ⇒ 面積可能**上升**（多了 ICG cell）
> 而 Fmax 上升。

### 2.2 B2（memory traceback）的預測：**這才是真正的樞紐**

register exchange 每 stage 改寫 64 × D 個 flop；記憶體式回溯每 stage 只寫 64 bits。
這是**數量級**的差別，不是百分比。

> **預測 P4**：B2 使 traceback 的功耗佔比從 43–54% 降到 **< 20%**。
> **預測 P5**：因此 `pm` 那 3.34% 的 SNR 依賴被稀釋得較少，
> 總功耗對 SNR 的變動 **上升到 2–5%**，但**仍不足以構成規格書 §7 想要的那條「曲線」**
> （判準見 §3）。

### 2.3 為什麼 P5 不是「兩邊押寶」

P5 給的是一個**區間**（2–5%）與一個**方向**（上升），而且它可以被證偽：
若實測 < 2%（沒上升）或 > 5%（上升到足以成為曲線），P5 就錯了。
機制推理（`pm` 是唯一帶 SNR 資訊的訊號，佔比 7–13%）給出上界：
即使 traceback 完全消失，SNR 依賴也不可能超過 `pm` 自身的全距 3.34%。
**所以 P5 的上緣 5% 其實已經是寬鬆的。**

## 3. null 是否存活的判準（**先寫死**）

以 `Q4_W10_D64` 掃 1→5 dB（與 M5 完全相同的 5 個點、相同激勵）為準：

| 判準 | 結論 |
|---|---|
| 總功耗全距 **< 2%** 且線性迴歸 **R² < 0.5** | **null 存活**：機制論文成立，且在最佳化過的設計上依然成立 |
| 總功耗全距 **≥ 2%** 且 **R² ≥ 0.5** | **null 消失**：標題改寫為「那個 null 是未最佳化設計的假象」 |
| 其餘（全距大但 R² 低，或反之） | **未解析**：如實記錄為「效應與雜訊同量級」，不得宣稱任一方向 |

**R² 是必要條件，不是裝飾**：5 個點的「看起來單調」不是證據——這是 M5 已經踩過一次的坑
（`2026-07-15-07`：pm 曾被寫成「單調上升」，實測 2 dB 有 0.3% 凹陷）。

**額外要求**：M5 的功耗量測是**單一 seed、3 frames、3090 cycles**，
在 SAIF 層級沒有任何 null 分布可以支撐「1.0% 是雜訊」。
M9 必須補 **≥ 8 個獨立 seed 在同一 SNR** 的重複，先建立 null 分布，
再判斷跨 SNR 的變動是否超出它。**沒有這個分布，上表的 2% 門檻無法被誠實套用。**

## 4. 不得因為 M9 而改變的事

1. **C2 必須先過。** B2 改變 traceback 架構 ⇒ 解碼位元的語意改變
   ⇒ 必須先在 `docs/traceback_convention.md` 追加第二套凍結語意、golden 端實作對應模式、
   C2 零 mismatch，**才准量功耗**。順序不可顛倒（CLAUDE.md §5.2）。
2. **annotation coverage ≥ 99%** 的硬性 gate 不放寬。
3. **B0 的數字原樣保留**，不因為有了 B1/B2 就重寫。M5 的結論是在 B0 上得到的，
   它的成立條件（未最佳化）現在被明確寫出來，而不是被抹掉。

## 勘誤 E-05（2026-07-31）

**原文（§3）**：判準表以「總功耗全距 < 2% **且**線性迴歸 **R² < 0.5**」為 null 存活的條件，
並註明「**R² 是必要條件，不是裝飾**」。

**更正**：**判準本身原樣保留、原樣套用**——M9 的裁決（gate `M9-4`）就是照這張表做的，
結論是「未解析」。本條不是要改判準，而是揭露它的一個侷限，讓單獨閱讀本文件的人看得到：

**n=5 時 R² 解析不出趨勢。** 同一個設計、同一組激勵，只是改寫 RTL 的 reset 寫法
（語意等價、功耗曲線幾乎重疊），R² 就從 B0 的 **0.478** 跳到 B0′ 的 **0.551**——
光是這樣就跨過了 **0.5** 的門檻。所以 R² 在這裡的判別力低於本文件寫下時的預期。

這正是本文件 §3「額外要求」那一段所預見的：沒有 ≥ 8 個獨立 seed 的 null 分布，
上表的門檻無法被誠實套用。該分布後來補上了（σ_null = 0.1415 mW），
並據以追加了斜率檢定（gate `M9-5`，`t = +1.82`）——但那是**事後追加**的檢定，
如實標示，不用它替換凍結判準。

**證據**：`data/gates.csv` 的 gate `M9-6`。

**發現於**：CHANGELOG `2026-07-30-03`。

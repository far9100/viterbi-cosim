## 0. 為什麼要重寫規格書 §0 的證偽條件

規格書 §0 寫的是：

> 在 η_PA ∈ [0.1, 0.5]、2.4 GHz free-space 或 indoor path loss 模型的合理參數範圍內，
> 若 d\* < 1 公尺或不存在，主張即告失敗。

**這個條件實質上不可能觸發。** 兩個理由：

1. **交叉點在數學上必然存在。** ΔE_tx(d) 隨 d^n 單調成長而解碼成本是固定的，故必有一點使兩者相等。
   「或不存在」這半句永遠為假。
2. **d\* 的量級遠大於 1 m。** 用 `docs/energy_model.md` 的常數粗算（見 §2），d\* 落在 13.7 m 到
   5.4 km 之間，跨越所有模型與 η_PA 的組合。距離 1 m 的門檻有一到三個數量級。

也就是說，這條件下的「主張」會**自動存活**，證偽框架失效。這不是失敗，是**門檻設得太低**。

處理方式：**§1 條件 1 原樣保留規格書的條件**（如實跑、如實裁決，不因為預期會過就跳過），
但**追加兩條真正咬得住的條件**（條件 2、3），指向本專案真正的貢獻——「字寬如何移動 d\*」。

## 1. 三條預先登記的證偽條件

### 條件 1（沿用規格書 §0，原文保留）

> 在 η_PA ∈ [0.1, 0.5]、2.4 GHz free-space 或 indoor path loss 模型的合理參數範圍內，
> 若 d\* < 1 公尺或不存在，主張即告失敗。

**事前預測：不會觸發。** 見 §2 的估計表。若竟然觸發，代表能量模型或 PPA 量測有嚴重錯誤，
須先追查錯誤而非宣稱發現。

### 條件 2（新增，針對頭條貢獻）

規格書的交付圖表 4 是「d\* vs Q——字寬如何移動臨界距離」，DoD §6 的結論句型是
「Q 從 3 bits 增至 5 bits 使 d\* 從 ___ 移到 ___」。這個句型**預設了 d\* 會明顯移動**。

**若 Q 從 3 增至 6 使 d\* 的變動量在模型 A 與模型 B 下皆小於 5%**，則「字寬移動臨界距離」
這個貢獻宣稱**失敗**。報告須如實改寫為：

> 效應存在但微弱：量化增益與解碼器能量對 d\* 的作用方向相反（見 §3），近乎相消。

### 條件 3（新增，針對本文件自己的事前估計）

**若實測的 d\* 對 Q 的變動量在模型 A 下超過 30%，或變動的「符號」與 §3 的預測相反**
（模型 A 應為正、模型 B 應為負），則本文件的事前機制推理被推翻。這是**有價值的正面結果**，
須追查機制，不得靜默調整模型去迎合數據。

## 2. d\* 的事前估計

由 `docs/energy_model.md` 的模型：

```
d*^n = [ E_dec(Q) + ΔE_circ ] · η_PA  /  [ ΔEbN0(Q) · N0 · L₁ ]

L₁      = 1.01174e4                       # 1 m 處的路徑損耗
N0      = 1.5940e-20 J                    # k·T₀·F，F = 6 dB
ΔE_circ = 0（模型 A） 或 P_c/R_s = 60 nJ（模型 B）
ΔEbN0(Q) = (Eb/N0)_未編碼 − (Eb/N0)_編碼(Q)      # 線性值，不是 dB
```

事前輸入（**這些是預測，不是量測——M1/M5 會把它們換成實測值**）：

| 量 | 事前值 | 依據 |
|---|---|---|
| (Eb/N0)_未編碼 @1e-5 | 9.588 dB = 9.096 | 閉式解；既有通訊模擬器已量到 9.5842 dB [9.5775, 9.5906] |
| (Eb/N0)_編碼 @1e-5（未量化、D=64） | 4.2 ± 0.15 dB = 2.630 | (133,171) union bound，d_free=10，c_d = 36/211/1404/11633… |
| ⇒ 編碼增益 | **5.39 dB** | 落在 G2b 的 [5.0, 5.6] 區間內 |
| 3-bit 量化損失 | +0.20 dB | Heller & Jacobs |
| 6-bit 量化損失 | +0.02 dB | |
| E_dec | ~100 pJ/info bit | 量級估計；Sky130、64-state、flop-based survivor mem |

**估計出的 d\***（E_dec = 100 pJ，F = 6 dB）：

| 模型 | η_PA | 自由空間 (n=2) | 室內 (n=3.5) |
|---|---|---|---|
| A（僅 PA + 解碼器） | 0.1 | 98 m | **13.7 m** |
| A | 0.5 | 219 m | 21.7 m |
| B（+ 電路功耗 + 2× airtime） | 0.1 | 2.40 km | **85 m** |
| B | 0.5 | 5.37 km | 135 m |

全部遠大於 1 m ⇒ **條件 1 預測不會觸發**。

注意模型 B 的 d\* 比模型 A **大**，不是小。加入電路功耗後，R=1/2 的編碼鏈路要付兩倍空中時間、
兩倍電路能量（60 nJ，比 E_dec 的 0.1 nJ 大 600 倍），編碼變得**更不划算**，交叉點因此往外推。

## 3. Q → d\* 的事前預測（本專案的頭條）

### 3.1 兩個方向相反的機制

Q 增加時，有兩件事同時發生，**方向相反**：

| 機制 | 方向 | 大小 |
|---|---|---|
| 量化損失變小 ⇒ 編碼增益變大 ⇒ ΔEbN0 變大 ⇒ 省更多發射能量 | **d\* 變小** | ΔEbN0(3)/ΔEbN0(6) = 6.342/6.454 = 0.9827 |
| PM 字寬 W 變大（8→12）⇒ ACS 資料路徑變寬 ⇒ E_dec 變大 | **d\* 變大** | 取決於 ACS 佔 E_dec 的比例 α |

令 **α = E_dec 中隨 W 縮放的比例**（ACS + PM 暫存器 + BMU），(1−α) 為 survivor 記憶體
（與 Q、W 皆無關）。W 從 8 到 12 是 1.5×，故：

```
E_dec(Q=6) / E_dec(Q=3) = (1 − α) + 1.5α = 1 + 0.5α
d*(Q=6) / d*(Q=3) = { (1 + 0.5α) × 0.9827 }^(1/n)
```

### 3.2 預測（模型 A）

| α（ACS 佔 E_dec 比例） | 自由空間 (n=2) | 室內 (n=3.5) |
|---|---|---|
| 0.15（**本專案的預測**：survivor 記憶體支配） | **+2.8%** | **+1.6%** |
| 0.50 | +10.8% | +6.1% |
| 0.85（ACS 支配） | +18.3% | +10.1% |

**最佳事前估計：α ≈ 0.15，故 d\* 隨 Q 增加約 +2% 至 +3%。**

α ≈ 0.15 的依據：D=32 時 survivor 記憶體是 64 states × 3D = **6144 個 flop**（Sky130 DFF ≈ 20 µm²
⇒ ~123,000 µm²），對上 ACS 的 640 個 PM flop + 32 個 butterfly（≈ 23,000 µm²）——面積上
**約 85% 是 traceback 記憶體**。能量的分佈未必與面積相同（clock gating 會大幅改變它），
所以 α 是本專案 M5 要**量出來**的東西，此處只給預測。

### 3.3 預測（模型 B）

模型 B 的 ΔE_circ = 60 nJ 完全淹沒 E_dec 的 0.1 nJ 級變化：

```
[E_dec(6) + 60000 pJ] / [E_dec(3) + 60000 pJ] ≈ 1.00012
d*(Q=6)/d*(Q=3) = { 1.00012 × 0.9827 }^(1/n)
```

| | 自由空間 (n=2) | 室內 (n=3.5) |
|---|---|---|
| 模型 B | **−0.87%** | **−0.50%** |

**模型 B 下 d\* 隨 Q 略微「減少」——與模型 A 的符號相反。** 因為 E_dec 的效應被電路能量淹沒，
只剩量化增益的效應。

### 3.4 這是一個「符號會翻轉」的預測

這是本文件最咬得住的一條：**同一組 RTL、同一組功耗量測，在兩個能量模型下 d\* 對 Q 的斜率符號相反。**
若實測的符號與此不符（模型 A 為負、或模型 B 為正），代表機制理解錯誤，須追查（條件 3）。

而且，由 §3.2 的表可以看出：**測到的 d\* 對 Q 的斜率，反過來就是 α 的量測**——也就是
「解碼器的能量到底花在 ACS 還是花在 traceback 記憶體」。這是這條驗證鏈路真正能回答、
而純軟體模擬回答不了的問題。

## 4. 與已核准計畫的差異（必須說明）

本專案的執行計畫（`fec-viterbi-cosim-spec-md-effervescent-hamster.md` §2.1）曾預測
「模型 A 下 d\* 移動約 7–12%」。**那個數字在此被修正為 +1.6% 至 +2.8%。**

原因：該估計用了 `E_dec(6)/E_dec(3) ≈ 1.2`（隱含 α ≈ 0.4），但同一份計畫的 §5/M5 又預測
survivor 記憶體佔 85%（即 α ≈ 0.15）。這兩者互相矛盾。本文件採用後者，因為它有具體的
flop 計數依據。7–12% 對應的是 α ≈ 0.5 的情形，已列在 §3.2 的表中作為對照。

此修正發生在**任何量測開跑之前**，不是事後調整。

# PM 字寬的界（G6 凍結）

> 這條界決定 12 個 (Q, W) 格點裡哪些是安全的。它必須在寫任何 RTL 之前定案，
> 因為 W 選錯的症狀是**高 SNR 出現神秘 BER floor、低 SNR 完全正常**——靠看 BER 曲線 debug 極慢。

## 1. 量化與 branch metric

以 Q-bit 無號軟值 `r ∈ [0, 2^Q − 1]`（`r` 小 = 傾向碼位元 0，見 §4）：

```
bm(c=0) = r
bm(c=1) = (2^Q − 1) − r
BM(碼字 c) = bm(c0) + bm(c1)  ∈  [0, λ_max]

λ_max = 2 · (2^Q − 1)
```

**互補性**：`bm(c) + bm(c ^ 3) = 2·(2^Q − 1) = λ_max`。
（因為 `bm_sym(c, r) + bm_sym(~c, r) = r + (2^Q−1−r) = 2^Q − 1`，兩個符號相加即得。）

這是 §trellis_convention P2 讓 butterfly 只需一個 BM 輸入的算術基礎。

## 2. 初始化（v1 規格書漏掉的那一項）

編碼器由狀態 0 出發，所以：

```
PM[0]   = 0
PM[s≠0] = PM_INIT
```

**`PM_INIT` 必須大到讓「假起始狀態」的路徑永遠贏不了。**

m = 6 步之後，任何狀態都能從狀態 0 抵達。在那之前，一條由 s≠0 假起始的路徑最好情況是
累積 0 的 branch metric；一條由狀態 0 出發的合法路徑最壞情況是累積 `t · λ_max`。
要讓合法路徑在 t ≤ 6 時始終勝出：

```
PM_INIT > 6 · λ_max        =>   PM_INIT = 6 · λ_max + 1
```

## 3. G6 的安全條件

Modulo（Hekstra）normalization 要能正確工作，任兩狀態的 PM 差（在無 wraparound 的參考
算術下衡量）必須小於 `2^(W−1)`，否則把差值解讀成 W-bit 有號數時符號會反轉，比較結果就錯了。

**PM spread 的最大值出現在 stage 1，不是穩態。**

| 時點 | spread 的上界 | 推導 |
|---|---|---|
| stage 1 | `PM_INIT + λ_max = 7·λ_max + 1` | 可達狀態（0, 1）的 PM ≤ λ_max；其餘狀態的 PM ∈ [PM_INIT, PM_INIT + λ_max] |
| 穩態 | `6 · λ_max` | 任何狀態都能在 m=6 步內由 `argmin` 狀態抵達，每步 branch metric ≤ λ_max；而 PM_min 不減（BM ≥ 0） |

所以**綁住整體的是初始化那一項**：

```
G6 安全條件：  2^(W−1)  >  7·λ_max + 1  =  14·(2^Q − 1) + 1
```

> **這是 v1 規格書的錯誤（修訂 B2）。** v1 只寫 `|PM_i − PM_j| < 2^(W−1)` 而沒有指明
> 初始化。若採「顯而易見」的 `PM_INIT = 2^(W−1) − 1`，**連安全格點都會在 stage 1 誤觸發
> assertion**，白燒一天，還會讓人不再信任 G6。

## 4. 安全 / 不安全格點表

| Q | λ_max | 需 2^(W−1) > | W=8 (128) | W=10 (512) | W=12 (2048) |
|---|---|---|---|---|---|
| 3 | 14 | 99 | **安全** | 安全 | 安全 |
| 4 | 30 | 211 | **不安全** | 安全 | 安全 |
| 5 | 62 | 435 | **不安全** | 安全 | 安全 |
| 6 | 126 | 883 | **不安全** | **不安全** | 安全 |

**12 個格點中 4 個先驗不安全**：`(Q=4,W=8)`、`(Q=5,W=8)`、`(Q=6,W=8)`、`(Q=6,W=10)`。

這帶來三件事：

1. **事前可預測的安全區** —— W 不是試出來的，是算出來的。
2. **G6 的負向測試不必人工造。** 規格書 §6 原本要求「故意把 W 調小到不足（例如 W=6）」；
   **不需要**——既有網格裡就有 4 個會壞的格點。
3. **「實測 Δ_max vs 最壞界」本身是一張有價值的圖。** 上界是充分條件，不是必要條件：
   實際的 spread 通常遠小於最壞界（尤其高 SNR）。所以某個「不安全」格點**未必真的 wrap**。
   這正是 G6 要用實測去回答的問題。

## 5. G6 的定義是「決策等價」，不只是 spread 不等式

`golden/viterbi_fx.py` 同時維護兩組 path metric：

| | 型別 | 用途 |
|---|---|---|
| `pm_mod` | `uint`，mod 2^W | **C2 的比對標的**（RTL 存的就是這個） |
| `pm_ref` | `int64`，無界 | G6 的參考 |

每個 stage 斷言：

```
由 pm_mod 導出的 ACS 選擇  ==  由 pm_ref 導出的 ACS 選擇
由 pm_mod 導出的 argmin    ==  由 pm_ref 導出的 argmin
```

**這才是 modulo normalization 正確性的證明。** spread 不等式只是一個便宜的充分條件，
順帶記錄下來（用來畫 §4.3 那張圖）。

## 6. Min-PM state 的取法（陷阱）

**不能對原始的 wrapped `pm_mod[]` 取 argmin**——它們會 wrap，`argmin` 會挑到錯的狀態。

正確做法（L2 / GPU / RTL 三方相同）：

```
d_s  = signed_W( pm_mod[s] − pm_mod[0] )      # 由 G6 保證 |spread| < 2^(W−1)，故合法
best = argmin_s d_s                            # 最低索引勝出
```

即：以狀態 0 當參考點相減，把差值解讀為 W-bit 有號數，再取最小。
RTL 端是 64 個 W-bit 減法器餵進一棵 6 層的比較樹（差值需要 W+1 bits 的有號數）。
